# 元数据、版本和置信度规则

## 文献、版本、附件是三个层次

- 文献条目保存所选版本的正式书目信息。
- arXiv v1/v2、会议版、期刊扩展版不能无条件当成完全相同的文本。普通出版版通常可与预印本挂在同一条目，但必须保留版本记录；有实质变化的扩展论文需要人工判断是否另立条目。
- 英文 PDF、中文 AI 译文、补充材料属于附件。译文不会自动成为一篇新的、以中文发表的文献。
- 本工具默认管理个人文献库，不操作群组库。

## 来源优先级不是“谁字段多就信谁”

1. 有明确 DOI 的目标出版版本：出版方记录，Crossref／DataCite 的对应记录；相互矛盾时停止推断。
2. 预印本：arXiv 官方 Atom 元数据，保留具体版本 URL、原始响应哈希。
3. 原文 PDF 首页：用于核验身份、作者、实际附件版本及补足官方记录；注意 PDF 文本提取不保证双栏作者阅读顺序。
4. 翻译 PDF、仓库索引、文件名：只作线索或翻译产物信息，不能覆盖权威书目数据。
5. AI 推测：不得写入 DOI、作者、日期、卷期页码、许可证等事实字段。

用户笔记不在这个优先级里：它们是用户创作，永不被自动来源笔记覆盖。

## 字段具体规则

| 字段 | 规则 |
|---|---|
| 标题 | 使用正式原文标题；DETR／AMIE 等额外简称可作标签，不擅自加入正式标题 |
| 作者 | 保留完整名字、Unicode 和顺序；arXiv 只有未结构化名字时使用 Zotero `name` 单字段；Crossref 给定 `given`/`family` 才使用拆分姓名 |
| 日期 | 所选预印本使用首次提交日期；所选出版版本使用该出版版本日期；更新、翻译、下载日期分别记录 |
| 文献类型 | 默认 arXiv 为 `preprint`，不是占位 `report`；验证正式出版记录后才能切 `conferencePaper` 或 `journalArticle` |
| DOI | 只填对应版本已核验的 DOI；不凭 `10.48550/arXiv...` 模式生成一个“看起来正确”的 DOI |
| 摘要 | 采用所选版本官方摘要；AI 中文摘要属于单独笔记 |
| 期刊／会议、出版社、卷期、页码 | 同一个已核验出版版本的字段；不能靠“Accepted to CVPR”填出论文集名、DOI 或页码 |
| 语言 | 原文语言和附件语言分开；目前 arXiv Atom 不直接提供确证语言字段，核心 resolver 不自动填它 |
| 版权／许可证 | 只记录确证来源；arXiv 论文不是统一 CC BY，不从某一份译文模板推广到所有论文 |
| 主题 | 按内容／标题规则分类，有不确定性则放“待分类”；分类不是正式出版元数据 |

`metadata_complete_for_selected_edition` 只表示计划中已核验的所选版本字段全部落库，不意味着权威来源里没有的字段也“完整了”。空缺卷期页码可能是正确状态。

## 查重与冲突

- 优先匹配正规化 DOI、去版本号的 arXiv ID；不要从摘要或参考文献中提取本条目的身份。
- 同一 arXiv 版本系列不因 `v1`/`v2` 重复建条目。
- 同标题、缺强标识符：只标为候选，不自动合并、不再重复创建。
- 同强标识符有多条记录：停止该篇入库，报告重复，合并需用户确认。
- 同一 DOI／arXiv 有矛盾：停止，不能凭星标数或插件返回成功就相信。
- PDF 按 SHA-256 去重，不仅按文件名；不同内容同名不覆盖。
- 原有非空字段默认保留。允许只增加精度的同年日期补齐；改年份、作者、标题、类型需针对性授权。

## 日期与身份校验示例

即使文件放在 `2026/Paper_CN.pdf`，官方记录的首次提交日期也可能是 `2024-12-14`。目录年份和翻译日期不能用作论文发表日期。

缺 ID 时应将 PDF 的完整标题和作者集合与官方记录匹配，而不是凭模型短名称猜测。译文抽取到的作者排列若与官方次序不同，书目记录应使用官方次序，并保留识别依据。

最新元数据不保证匹配中文 PDF 所翻译的版本。不能因为查询返回 `v3` 就给未知版本译文标注“v3 中文版”。
